Every query goes through the sieve.

Crivo is Portuguese for sieve. It turns a policy file into a local CLI for a pre-production Postgres. The AI queries the database through it, and every statement goes through the real Postgres parser before it gets there.

  • Deny by default. What the policy does not mention does not exist for the AI.
  • Fail closed. Ambiguous column, unknown node or a function outside the allowlist: refused.
  • Runs what it validated. The database gets the rewritten SQL, never the original string.

    A policy that fits on one screen
    
      
    The .crivo file says what the AI may read and write, table by table. This is the example from the repository, the same one that answered the queries above. Keywords are English; its comments, like the schema, are Portuguese.
    
      
    
        
    __POLICY__
    
        
    
          
    read, insert,
    update, delete
    The four actions. DDL, TRUNCATE, COPY, SET and the like never get through.
    
          
    (a, b) · except(x)
    The columns an action reaches. A blocked column cannot even appear in a filter.
    
          
    where <expr>
    Row filter: on reads the table becomes a filtered subquery; on writes it is added to the WHERE.
    
          
    mask(col: …)
    partial, redact or hash, applied to the result.
    
          
    max N · limit N
    Cap on rows a write may touch (above it, rollback) and on rows a read returns.
    
          
    deny
    The table vanishes for the AI. pg_catalog and information_schema always do.
    
        
    
      
    
    
    
  
    

  
    
    
    
      
    The path of a query
    
      
    Parse with pg_query, check against the policy, rewrite, re-parse the result and demand the same AST, run it in a READ ONLY transaction with statement_timeout, and finally apply the masks.
    
      
      
    
        
    
          
    errors that teach
    Every refusal states the rule, the reason and what would be accepted, so the AI can fix the query on its own.
    
          
    exit codes
    0 ok, 2 refused, 3 invalid SQL, 4 database error, 5 configuration.
    
          
    audit
    Every call is logged to ~/.crivo/logs/<name>.jsonl, without the result data.
    
        
    
        
    
          
    Copilot
    vendas skill install writes the agent mode skill; skill vscode prints the auto-approve rules: reads and --dry-run run freely, a real write always takes a click.
    
          
    MCP
    vendas mcp serves the same tools over stdio. Real writes stay off until the server is started with --allow-exec.
    
        
    
      
    
    
    
  
    

  
    
    
    
      
    
        
    Even better on a read-only user
    
        
    The policy works on its own, but it is stronger as a second layer. crivo check warns when the connection user has too much privilege, and crivo grants writes the SQL for a least-privilege user from the policy itself, with per-column GRANTs.
    
      
    
      
    
    
  
    

  
    
    
    
      
    Installation
    
      
    A prebuilt binary for each platform, no Go or C compiler needed. The links below always point to the latest release.
    
      
    
        
        
        
      
    
      
    # Apple Silicon. On an Intel Mac, use crivo-macos-amd64 instead.
curl -fsSL https://github.com/__REPO__/releases/latest/download/crivo-macos-arm64 -o crivo
chmod +x crivo && sudo mv crivo /usr/local/bin/
crivo version
    
      
    curl -fsSL https://github.com/__REPO__/releases/latest/download/crivo-linux-amd64 -o crivo
chmod +x crivo && sudo mv crivo /usr/local/bin/
crivo version
    
      
    # PowerShell: downloads into a folder of yours and adds it to your user PATH
$dir = "$env:LOCALAPPDATA\crivo"; New-Item -ItemType Directory -Force $dir | Out-Null
Invoke-WebRequest https://github.com/__REPO__/releases/latest/download/crivo-windows-amd64.exe -OutFile "$dir\crivo.exe"
[Environment]::SetEnvironmentVariable("Path", "$([Environment]::GetEnvironmentVariable('Path','User'));$dir", "User")
# open a new terminal and run:
crivo version
    
      
    On macOS, downloading from the terminal avoids Gatekeeper quarantine, which refuses binaries without a developer signature when they come from a browser. Crivo is a terminal program: on Windows, double-clicking the .exe only shows the help.

    From file to Copilot
    
      
    No database at hand? Try the policy against DDL: --schema-sql takes the repository's testdata/schema.sql or the output of pg_dump --schema-only.
    
      
    crivo init "postgres://svc_app@pg-hml:5432/vendas?sslmode=verify-full"   # vendas.crivo, everything denied
$EDITOR vendas.crivo                                                   # open up what the AI may do
crivo secret set vendas                                                # password in the OS keychain
crivo check vendas.crivo                                               # syntax, semantics and real schema
crivo test vendas.crivo "SELECT * FROM clientes"                       # decision and rewritten SQL
crivo build vendas.crivo                                               # builds ./vendas with the policy embedded
./vendas skill install                                                 # Copilot skill in the workspace
